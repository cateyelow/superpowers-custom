DEFECT 1
what: The "Remove" control is completely dead for the whole 2-second upload — a user cannot take a file out of the list once Upload is pressed.
where: upload.html:408 (fileList.replaceChildren) + upload.html:517 (render() called from every requestAnimationFrame tick); .file-item .remove-button
repro: Loaded 3 files, clicked Upload, then pressed mouse down on a Remove button and released after 0 / 30 / 60 / 100 / 150 ms (5 separate runs). Item count stayed 3 -> 3 in ALL five runs. Identical mouse down/up sequences at the same delays while idle removed the item every time (3 -> 2). Cause measured: a MutationObserver on #file-list recorded 122 childList/characterData mutations during one 2.6 s upload, and a reference held to the first Remove button reported document.contains(ref) === false 200 ms into the upload — the <li> is destroyed between mousedown and mouseup so no click event is ever produced.
severity: blocking
category: logic

DEFECT 2
what: Keyboard focus is thrown away the instant an upload starts and is never restored, dumping the user at the top of the document mid-task.
where: upload.html:408 (replaceChildren destroys the focused node), upload.html:517
repro: Focused the first Remove button (document.activeElement === BUTTON.remove-button), clicked Upload. 300 ms later document.activeElement === BODY; still BODY after the upload finished. Pressing Enter at that point did nothing (item count stayed 3) because the focused button no longer exists.
severity: blocking
category: a11y

DEFECT 3
what: The entire file list sits inside aria-live="polite" and is rebuilt about 60 times a second during an upload, so a screen reader is flooded with re-announcements of the whole list.
where: upload.html:313 (<ul id="file-list" aria-live="polite">), fed by upload.html:408 + upload.html:517
repro: Measured aria-live ancestor of the per-frame changing status text (".file-status" showing "47%") = UL#file-list[aria-live=polite]. A MutationObserver on that element counted 122 childList/characterData mutations over a single 2.6 s upload; every one replaces all list children, so a polite region queues ~120 full-list announcements. No aria-busy is set anywhere on the page (measured 0 elements with aria-busy).
severity: blocking
category: a11y
