DEFECT 1
what: While an upload is running, clicking "Remove" on a file does nothing — the file stays in the list, no matter how many times you click.
where: upload.html:351-413 (render) called from upload.html:517 inside the requestAnimationFrame loop (upload.html:508-527); target control is li.file-item .remove-button
repro: Isolated Chromium (Python Playwright, headless, file:// URL). Added 3 files, clicked Upload, then pressed and released the real mouse on the 2nd "Remove" (mouse.move -> mouse.down -> hold -> mouse.up). Result table (hold time -> was the file removed?): idle page 0/16/32/60/120/250ms -> removed every time; during upload 16/32/60/120/250ms -> NEVER removed (only an unrealistic 0ms press/release worked). A capture-phase listener on #file-list recorded zero click events during upload. Cause is measurable: render() runs on every animation frame during upload and calls fileList.replaceChildren (upload.html:408) — 123 childList mutations measured across one 2s upload — so the <li> that received mousedown is destroyed before mouseup and the browser never synthesises a click.
severity: blocking
category: state
