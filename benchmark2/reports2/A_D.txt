DEFECT 1
what: Dropping a file anywhere on the page except the drop zone (a near miss on the card, the heading, the file list) is not intercepted, so the browser leaves the page and opens the dropped file, destroying the entire selected-file list.
where: upload.html:437-465 (drag handlers are bound only to #drop-zone; no document/window dragover or drop listener exists)
repro: Isolated headless Chromium, file:// URL. Dispatched a real DragEvent pair carrying a File onto h1 and onto .upload-card: dragoverPrevented=false, dropPrevented=false, itemsAfter unchanged (0 added). With neither dragover nor drop cancelled outside the zone, the default navigate-to-file action runs and the page state is gone.
severity: blocking
category: state

severity: blocking
category: a11y
