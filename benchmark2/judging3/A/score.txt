- CONFIRMED_REAL | Drop zone violates WCAG 2.5.3 Label in Name: aria-label "Choose files or drop files here" does not contain the visible label "Drop files here or click to browse" | Opened the page in an isolated headless Chromium. #drop-zone outerHTML has role="button" aria-label="Choose files or drop files here"; innerText is "↑ / Drop files here or click to browse / You can select multiple files". page.accessibility.snapshot() names the node "Choose files or drop files here". The visible string is not a substring of the accessible name, so the Level A criterion fails and a speech-input user reading the on-screen words gets no match.
- CONFIRMED_REAL | Drop zone suppresses the focus outline and signals focus only by a border tint that is a 1.96:1 change from the unfocused colour, and that tint is the identical declaration used for :hover | Dumped the stylesheet: ".drop-zone:hover, .drop-zone:focus-visible { border-color: rgb(78,110,232); background: rgb(241,244,255); outline: none; }" — one shared block, so focus and hover render identically. Computed styles with the 160ms transition settled: unfocused border-top-color rgb(159,172,204), outline "none 0px", box-shadow none; after Tab (matches(':focus-visible')===true) border-top-color rgb(78,110,232), still outline none / no box-shadow. Measured the change-of-contrast between the two border colours = 1.96:1; WCAG 1.4.11 (and 2.2 SC 2.4.13) require 3:1 for a focus indicator expressed as a colour change on an already-present element. Element screenshots of the two states confirm the only difference is the dashed border hue plus a 1.05:1 background shift.
