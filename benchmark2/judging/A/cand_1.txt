DEFECT 1
what: While an upload is running, the per-file "Remove" buttons stop working entirely — clicking one does nothing, so a file cannot be taken out of the list until the upload finishes.
where: upload.html:408 (`fileList.replaceChildren(fragment)` inside render(), driven by the requestAnimationFrame loop at upload.html:517) — control: `.file-item .remove-button`
repro: Added 3 files (one.txt, two.txt, three.txt), clicked Upload, then 600ms later performed a real mouse click (mousedown, hold, mouseup) on the third item's Remove button. List still showed ["one.txt","two.txt","three.txt"] — nothing removed. Repeated with 5ms, 80ms and 150ms hold: all failed. Identical click while idle removed the file (list became ["one.txt","two.txt"]). Cause verified: after 2 animation frames of an upload, the captured Remove button node was no longer in the document (document.contains(btn) === false, node replaced) — the whole list is rebuilt ~60x/second (measured 122 list rebuilds during one 2.0s upload), so mousedown and mouseup never land on the same element.
severity: blocking
category: state

DEFECT 2
what: A file dropped anywhere on the page other than the dashed drop zone is not added to the list — the browser takes over the drop and opens the dropped file instead, pulling the user out of the app.
where: upload.html:437-465 — dragenter/dragover/dragleave/drop listeners are bound only to `#drop-zone`; nothing cancels the default drag behaviour at document level
repro: With one file already queued, dispatched a real drag sequence (CDP Input.dispatchDragEvent: dragEnter/dragOver/drop with a real file) onto the card at the "Upload files" heading, ~90px above the dashed zone. The browser opened the dropped file itself (a `file:///.../alpha.txt` tab appeared) and the widget's list was unchanged (still 1 item, dropped file never added). Also measured: DragEvent('dragover') and DragEvent('drop') dispatched on document.body and on `.upload-card` both return defaultPrevented === false, i.e. the page never cancels the browser default.
severity: blocking
category: logic
