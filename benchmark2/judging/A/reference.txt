DEFECT 1
what: While an upload is running, the per-file "Remove" button is dead — a normal-length mouse click on it does nothing, so the user cannot take a file out of the list during the upload.
where: upload.html:508-527 (updateProgress rAF loop calling render()) + upload.html:408 (fileList.replaceChildren) + upload.html:467-476 (delegated click handler); selector .file-item .remove-button
repro: Add 3 files, click Upload, then press-and-hold the 2nd file's Remove for 30/60/100/200 ms and release (real mouse down+up via Playwright). File count stays 3 in all four trials. The identical press-and-hold with no upload running removes the file every time (3 -> 2 at all four hold durations). Control: "Clear all" (the one control that is not re-rendered) does work during an upload. Cause: render() is called on every animation frame (~61 renders/sec, measured), so replaceChildren destroys the button between mousedown and mouseup and no click event ever reaches it.
severity: blocking
category: logic

DEFECT 2
what: During an upload, keyboard focus cannot stay anywhere inside the file list — focus is thrown to <body> within one animation frame, so a keyboard or screen-reader user cannot reach or operate any Remove button while uploading.

severity: blocking
category: a11y
